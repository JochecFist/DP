\section{Použité technologie}
\subsection{Unreal Engine}

Unreal Engine\cite{Unreal2025} je multiplatformní herní engine vyvíjený společností Epic Games, který slouží k~tvorbě 3D aplikací v~reálném čase, včetně videoher, vizualizací, simulací nebo interaktivních prostředí. Jeho jádrem je výkonově orientovaný kód napsaný v~jazyce C++, který poskytuje vývojářům přímý přístup k~nízkoúrovňovým systémům enginu a~vysokou míru kontroly nad chováním runtime prostředí. Unreal Engine je dlouhodobě používán ve vývoji komerčních titulů i~ve filmové produkci díky schopnosti zpracovávat složité grafické scény s~vysokou vizuální kvalitou.

V~projektu je použita verze \textbf{Unreal Engine 5.2}, která rozšiřuje možnosti reálného 3D renderování a~vývoje prostředí spolu s~nástroji pro procedurální generování obsahu a~rozsáhlou podporou pro tvorbu světů ve vysokém rozlišení. Verze 5.2~přináší řadu technických vylepšení pro tvorbu reálného času obsahu, včetně nástrojů pro generování velkých scén přímo v~enginu a~rozšířenou podporu pro materiály a~vizuální efekty.

Unreal Engine je navržen tak, aby umožňoval tvorbu komplexních 3D prostředí pomocí kombinace programování v~C++ a~vizuálního skriptování přes systém Blueprint. Tento přístup umožňuje zachovat výkonově efektivní kód i~rychlé prototypování logiky bez psaní rozsáhlých bloků textového kódu. Kromě toho engine poskytuje integrované nástroje pro animace, fyziku, simulace, světelné modely, efekty částic a~další subsystémy, které usnadňují implementaci složitých herních či simulačních mechanik.

Unreal Engine nachází uplatnění nejen ve vývoji videoher, ale i~v~architektonické vizualizaci, filmové produkci nebo průmyslových simulacích, kde je kladen důraz na reálné osvětlení, stíny a~materiálové vlastnosti scény. Schopnost kombinovat tyto prvky v~reálném čase poskytuje vývojářům platformu pro testování, prototypování i~prezentaci výsledků v~konzistentním prostředí.

\subsubsection{Důvody volby Unreal Engine}

Volba prostředí Unreal Engine vychází z~jeho předchozího využití v~bakalářské práci \cite{Jochec2023} a~z~dalších technických důvodů:

\begin{enumerate}
    \item \textbf{Výkon a~3D grafika:} Engine je optimalizovaný pro rozsáhlé 3D scénáře s~vysokou vizuální kvalitou a~podporuje pokročilé technologie jako Lumen a~Nanite, které umožňují dynamické osvětlení a~detailní geometrické vykreslení bez výrazných kompromisů na výkonu.
    \item \textbf{Programování v~C++:} Jazyk C++ poskytuje přímý přístup k~výkonově kritickým částem enginu a~je vhodný pro aplikace, kde je rychlá odezva a~efektivní využití hardwaru klíčové; v~tomto je výhodou oproti jazykům vyšší úrovně jako C\# .
    \item \textbf{Systém Blueprint:} Vizuální skriptování přes Blueprint usnadňuje tvorbu logiky, interakcí a~dalšího chování bez nutnosti hluboké znalosti programovacích jazyků. To snižuje bariéru při vývoji pro části týmu zaměřené více na design než na kódování.
    \item \textbf{Assety a~nástroje:} Unreal Engine integruje nástroje a~workflow pro práci s~3D modely, animacemi i~zvukem přímo v~editoru a~podporuje import dat z~externích aplikací bez nutnosti ruční konverze.
    \item \textbf{Rozšiřitelnost:} Engine nabízí systém pluginů a~rozhraní API, které umožňuje přidávat vlastní moduly, nástroje nebo rozšíření funkčnosti bez zásahu do hlavní kódové báze projektu.
\end{enumerate}

\subsubsection{Nevýhody a~technické kompromisy}

Použití Unreal Engine oproti jiným enginům přináší i~určité technické kompromisy:

\begin{enumerate}
    \item \textbf{Vyšší hardwarové nároky:} Unreal Engine 5~a~jeho nástroje pro vysokou grafickou kvalitu obvykle vyžadují výkonnější hardware, zejména při práci s~velkými scénami nebo pokročilými efekty. To může být ve srovnání s~alternativami jako Unity či Godot náročnější pro vývojové i~cílové prostředí.
    \item \textbf{Složitost a~křivka učení:} Vzhledem k~rozsahu nástrojů a~možností enginu může být jeho zvládnutí náročnější, zejména pro vývojáře bez předchozích zkušeností s~C++ nebo komplexními 3D enginy.
    \item \textbf{Velikost projektu a~náročnost správy:} Projekty v~Unreal Engine mohou mít větší velikost a~složitější strukturu než v~jednodušších enginových řešeních, což vyžaduje pečlivé řízení závislostí a~assetů během vývoje.
\end{enumerate}

\subsection{Visual Studio}

Visual Studio je integrované vývojové prostředí (IDE) vyvíjené společností Microsoft. Slouží k~psaní, kompilaci a~ladění programového kódu v~různých jazycích, včetně C++.

V~kontextu Unreal Engine se Visual Studio běžně používá jako primární nástroj pro vývoj C++ kódu, protože poskytuje přímou integraci s~buildovými nástroji, laděním a~správou projektů. Podpora Unreal Engine v~rámci Visual Studia zahrnuje například možnost rozšířit editor o~nástroje pro generování tříd, prohlížení logů nebo debugování kódu vytvořeného z~projektu Unreal Engine (pomocí volitelné sady \uv{Visual Studio Tools for Unreal Engine} a~příslušných komponent).

Pro čisté C++ projekty Unreal Engine je Visual Studio doporučený editor, protože usnadňuje generování projektových souborů, správu závislostí a~ladění. Unreal Engine poskytuje nástroje pro konfiguraci a~synchronizaci s~Visual Studiem a~tento workflow je v~oficiální dokumentaci považován za standardní způsob nastavení vývojového prostředí pro C++ programování s~Unreal Engine.

V~případě tohoto projektu však Visual Studio bohužel nepůsobilo jako použitý nástroj, protože vývoj probíhal bez psaní C++ kódu. Unreal Engine umožňuje tvorbu herní logiky i~interakcí prostřednictvím vizuálního systému Blueprint, který nevyžaduje tradiční IDE ani textový C++ editor. V~takových případech může být práce nad Unreal projektem realizována přímo v~editoru enginu bez zásahu do textového programovacího prostředí. Pokus o~úpravu či rozšíření dostupných algoritmů NevarokML nebyl úspěšný z~důvodů popsaných v~následujících kapitolách této práce.

\subsection{NevarokML}
NevarokML\cite{Nevarok2025} je plugin pro Unreal Engine 5, který umožňuje přímou integraci strojového učení — konkrétně zpětnovazebního učení — do herních nebo simulačních projektů. Plugin je založen na knihovně Stable-Baselines3 a~zpřístupňuje oblíbené RL algoritmy jako PPO, A2C, DDPG, DQN, SAC a~TD3, které agentům umožňují učit se optimálnímu chování metodou pokus–omyl.

NevarokML podporuje hlavně jednoagentní interakce, kde víceagentní interakce jsou pouze zatím v~plánu. Architektura NevarokML funguje na principu klient–server: Unreal Engine zde působí jako serverová část, která simuluje prostředí a~chování agentů, zatímco pythonový klient provádí strojové učení pomocí algoritmů ze Stable-Baselines3.

Komunikace mezi Unreal Enginem a~Python klientem probíhá prostřednictvím síťového spojení (socketů) s~využitím formátu JSON, který slouží k~přenosu informací o~stavu prostředí, zejména pozorování, akcí a~odměn.

Po dokončení trénování jsou výsledné váhy modelu exportovány do formátu ONNX a~následně nasazeny přímo do Unreal Enginu jako objekt typu NNEModelData prostřednictvím systému Neural Network Engine.

Framework NevarokML tak zajišťuje technickou vrstvu posilovaného učení pro prostředí UE5, zatímco implementace samotného trénovacího modulu a~jeho prostředí je plně v~kompetenci vývojáře. Trénovací modul musí znát velikost akčního a~pozorovacího prostoru a~mít přístup k~definici prostředí, agenta, kterého řídí, i~dalších interagujících objektů.

V~samotném prostředí jsou následně definovány konkrétní pozorovací prvky, akční prvky a~odměnová logika, které určují, jaká data agent získává, jaké akce může provádět a~jakým způsobem je jeho chování hodnoceno.

ONNX\cite{ONNX2025} (Open Neural Network Exchange) představuje otevřený formát a~ekosystém navržený tak, aby umožnil snadný přenos již natrénovaných modelů hlubokého učení mezi různými vývojovými frameworky, platformami a~typy hardwaru — bez potřeby složité konverze nebo zdlouhavých procesů.

Neural Network Engine (NNE)\cite{NNE2025} je plugin určený pro provádění inferencí neuronových sítí v~reálném čase přímo v~prostředí Unreal Engine. Plugin využívá formát ONNX, který umožňuje spouštění modelů exportovaných z~běžně používaných frameworků strojového učení, jako jsou PyTorch, TensorFlow nebo MXNet, ve formátu .onnx bez nutnosti dalšího převodu.

\begin{enumerate}
\item Vytvoření prostředí:
\begin{itemize}
\item Práce začíná vytvořením Blueprint třídy děděné z~NevarokMLEnviroment, kde se definují základní události OnInit, OnStep a~OnReset, které řídí logiku prostředí a~průběh epizod.
\end{itemize}
\item Trenérský modul:
\begin{itemize}
\item Následuje vytvoření Blueprintu děděného z~NevarokMLTrainer, kde se nastavují pozorovací a~akční prostory (OnConstruct) a~spouští se samotný trénink (OnStart).
\end{itemize}
\item Implementace v~úrovni:
\begin{itemize}
\item Trenér i~prostředí se umisťují do scény v~Unreal Enginu, přičemž trenér odkazuje na prostředí a~celý trénink začíná při spuštění úrovně.
\end{itemize}

\item Sledování učení:
\begin{itemize}
\item Pro vizualizaci průběhu učení se může použít TensorBoard, který umožňuje sledovat vývoj odměn, změny v~politice agenta nebo ladění hyperparametrů.
\end{itemize}
\end{enumerate}

Plugin je dostupný pro Unreal Engine ve verzi 5.2~a \uv{výše} (bohužel pro vyšší verze je plugin nepoužitelný kvůli přepisu kódu NNE a~taky starému kódu NevarokML, který už delší chvíli nebyl aktualizován) a~po jeho aktivaci je nutné spustit i~backend klienta a~ověřit připojení mezi Unreal Enginem a~Pythonovým prostředím.

Hlavní vlastnosti a~využití:
\begin{enumerate}
\item Podpora Blueprintů i~C++:
\begin{itemize}
\item Plugin lze plně využívat jak přes vizuální skriptování, tak i~přes nativní C++ rozhraní pro pokročilejší zásahy (ale není doporučované)
\end{itemize}
\item Cross-platform nasazení:
\begin{itemize}
\item I~když trénink typicky probíhá na Windows, natrénované modely je možné nasadit na jakoukoli platformu podporovanou Unreal Enginem.
\end{itemize}
\item Vhodné pro výuku a~výzkum:
\begin{itemize}
\item Plugin je volně dostupný pro nekomerční využití, což z~něj činí ideální nástroj pro akademické projekty, simulace nebo vývoj prototypů.
\end{itemize}
\end{enumerate}

\section{Návrh hry}
\subsection{Návrh prostředí hry}
Prostředí, ve kterém bude autonomní agent fungovat, lze realizovat různými způsoby – od jednoduchých po technicky náročnější. Mezi přístupnější varianty patří využití herních enginů, jako je Unity nebo Unreal Engine, zatímco pokročilejší řešení zahrnuje programování vizualizace od základu pomocí nízkoúrovňových API, jako jsou OpenGL nebo DirectX.

V~tomto projektu bude vizualizace agenta realizována v~prostředí Unreal Engine formou střílečky z~pohledu první osoby. Prvním krokem bude vytvoření herní mapy, která umožní volný pohyb hráče i~postavy řízené umělou inteligencí.

Mapa bude inspirována městským náměstím po bitvě. Její střed bude tvořit park s~bankovní budovou, přičemž park bude vlivem zpustošení téměř prázdný a~bankovní budova obklopena barikádami. Právě v~této budově se hráč po spuštění hry objeví.

V~objektu bude možné nalézt zbraně a~zásobovací box obsahující zbraně a~brnění, které hráč využije v~boji. Bankovní budova spolu s~přilehlým parkem obklopeným barikádami bude sloužit jako hlavní bojová aréna pro souboje mezi člověkem a~umělou inteligencí. Stejná mapa bude rovněž využita pro souboje mezi dvěma postavami.

Pro vyvážení obtížnosti budou nepřátelé po smrti odhazovat sbíratelné předměty, jako jsou lékárničky a~zásobníky munice, které hráč využije k~doplnění zdraví nebo střeliva.

Součástí uživatelského rozhraní bude tzv. HUD (Head-Up Display), který bude zobrazovat klíčové herní informace – aktuální stav zdraví, zásoby energie, počet nábojů a~další. Z~tohoto rozhraní bude možné přistupovat jak k~hlavnímu menu, tak k~pauzovací nabídce.

Celá hra bude strukturována do kol. Po spuštění prvního kola se zavřou dveře banky, přičemž venku bude umístěna další bedna s~vybavením, která umožní výměnu zbraní a~brnění. V~každém kole bude úkolem hráče eliminovat předem daný počet nepřátel. Po jejich porážce se aktuální kolo uzavře a~automaticky začne nové – s~větším počtem protivníků. Tím vznikne dynamický cyklus, který otestuje schopnosti hráče i~chování autonomního agenta v~různých podmínkách.

Prostředí a~větší množství kódu Blueprintů bylo převzat z~mé bakalářské práce\cite{Jochec2023}. Většina tohoto kódu a~i~prostředí byla nakonec kvůli potřebným rozsáhlým úpravám a~také chybám, co zůstali z~dob bakalářské práce, potřeba odstanit (když možné tak upravit), aby bylo prostředí a~zbytek kódu použitelný pro nového agenta.

\subsection{Návrh agenta}
Cílem práce je vytvořit agenta řízeného pomocí technik strojového učení, který se dokáže adaptovat v~herním prostředí. Agent by měl být schopen se v~prostředí zorientovat, přiblížit se ke svému cíli (hráči) a~efektivně využít střelnou zbraň k~jeho eliminaci.

Agent nebude ovládán předem nadefinovanými skripty, ale bude se učit na základě zkušeností pomocí zpětnovazebního učení. Učící algoritmus je založen na metodě Proximal Policy Optimization (PPO), která je známá svou stabilitou při učení v~komplexních a~nestacionárních prostředích, jakými jsou moderní videohry. PPO umožňuje efektivní učení politiky i~ve vysokodimenzionálním stavovém prostoru a~při diskrétním akčním prostoru. Zároveň omezuje velikost aktualizací politiky, čímž zabraňuje nestabilnímu chování během tréninku. Ve srovnání s~ostatními algoritmy dostupnými v~knihovně NevarokML představuje PPO vyvážený kompromis mezi stabilitou učení, implementační složitostí a~praktickou použitelností.

Přibližný algoritmus agenta vytvořeného pomocí NevarokML je schematicky znázorněn na obrázku~\ref{obrAlg}. Tento vývojový diagram ilustruje jednotlivé fáze interakce agenta s~prostředím — od sběru pozorování, přes předání dat do neuronové sítě, predikci a~provedení akce, až po získání odměny, uložení zkušeností a~následný trénink modelu.

Přestože framework NevarokML v~teorii umožňuje přímou modifikaci architektury neuronové sítě skrze C++, tuto možnost se nepodařilo v~rámci práce úspěšně zrealizovat (viz následující kapitola). Veškerá zlepšení jsou proto zaměřena na okolní prvky učicí smyčky, zejména na strukturu pozorování, množinu dostupných akcí a~definici odměn. Tyto prvky mají přímý vliv na kvalitu získané politiky a~zároveň nepřímo ovlivňují i~výslednou architekturu neuronové sítě prostřednictvím procesu učení.

Aby měl agent dostatečný přehled o~situaci, budou mu prostřednictvím funkce CollectObservations předávány relevantní informace, na jejichž základě bude činit rozhodnutí. Tyto pozorování mu umožní vyhodnotit aktuální stav prostředí a~adekvátně reagovat.

\newpage

Agent bude mít přístup ke třem základním typům akcí:
\begin{itemize}
\item Pohyb,
\item Rotace,
\item Střelba – za předpokladu splnění podmínek (např. není aktivní cooldown, hráč se nachází v~zorném poli apod.).
\end{itemize}

Tyto akce budou implementovány ve funkci ApplyActions, která interpretuje výstup neuronové sítě jak během tréninku, tak i~v~nasazení.

Jádrem efektivního učení bude systém odměn implementovaný ve funkci HandleRewards, jenž určuje, jak bude agent penalizován nebo odměňován za své chování. Bude například odměňován za správnou rotaci, pohyb směrem k~cíli nebo udržování optimální vzdálenosti. Zároveň bude trénink omezen tak, aby agent nebyl motivován pouze maximalizovat počet bodů bez reálného splnění cíle. Veškerá motivace bude přímo vázána na výsledek boje.

Na základě tohoto návrhu se očekává, že agent:
\begin{enumerate}
\item Rozpozná pozici cíle na základě poskytnutých pozorování,
\item Přiblíží se na efektivní vzdálenost,
\item Srovná rotaci tak, aby směřoval k~cíli,
\item Zahájí palbu a~pokusí se cíl eliminovat.
\end{enumerate}
